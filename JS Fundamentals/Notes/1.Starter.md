# JavaScript Basics

> [!summary] Summary
> JavaScript is a programming language used to make websites interactive and dynamic. It is **synchronous and single-threaded by default**, but supports asynchronous execution through **callbacks, promises, and async/await**.

## 1. Sync vs Async

| Type             | How it is handled                                   |
| ---------------- | --------------------------------------------------- |
| **Synchronous**  | Directly by the **Call Stack**                      |
| **Asynchronous** | **Call Stack + Browser APIs + Queues + Event Loop** |

See also: [[Event Loop]], [[Promises]], [[Callbacks]]

## 2. Execution Context

Everything in JS runs inside an **Execution Context**, which is created by the JS engine (V8 in Chrome and Node.js).

Each execution context has two parts:

- **Memory environment** (variable environment): where all variables and functions are stored.
- **Code environment** (thread of execution): where the code actually runs **line by line**. This is why JS is **single-threaded and synchronous**.

### Types of execution context

|Type|Description|
|---|---|
|**Global Execution Context**|Created once when the program starts|
|**Function Execution Context**|A brand-new context created every time a function is called|

### Two phases of every execution context

1. **Memory allocation phase**
    - `var` variables → `undefined`
    - `let` / `const` → _uninitialized_ (this is the [[Temporal Dead Zone]])
    - Functions → the **full function body** is stored
2. **Code execution phase**
    - Goes through the code line by line and executes it.

> [!note] This memory phase is what causes [[Hoisting]].

## 3. Primitive vs Non-Primitive (Heap Memory)

|Kind|Types|Stored where|
|---|---|---|
|**Primitive**|Number, String, Boolean, Undefined, Null, BigInt, Symbol|Directly in the Execution Context's memory environment|
|**Non-primitive**|Array, Object (and functions)|In **Heap memory**; only a **reference** is stored in the memory environment|

```text
JavaScript Engine (V8)
│
├── Call Stack
│   └── Global Execution Context
│       └── Variable Environment (Memory)
│            age  → 21
│            name → "Yug"
│            user → Ref ───────────┐
│            arr  → Ref ────┐      │
│                           │      │
└── Heap Memory             │      │
    ├── arr  → [1, 2, 3] ◄──┘      │
    └── user → { city: "Navsari" }◄┘
```

See also: [[Shallow Copy vs Deep Copy]]

## 4. JS Architecture Hierarchy

> [!info] **V8** is Google's JS engine, used in Chrome (Chromium) and Node.js. Other browsers use their own engines: Safari uses _JavaScriptCore_ and Firefox uses _SpiderMonkey_.

### V8 Engine

- **Call Stack**: holds execution contexts (global / function), each with a Memory phase and a Code phase.
- **Memory Heap**: stores non-primitive data.

### Browser Runtime

- **Event Loop**: keeps checking whether the call stack is empty (all synchronous code done). When it is empty, it pushes tasks from the queues onto the call stack.
- **Microtask Queue** (higher priority): promises, async/await
- **Task Queue / Macrotask Queue/ CallBack Queue**: `setTimeout`, `setInterval`, DOM events

> [!tip] Microtasks always run **before** the next macrotask.
