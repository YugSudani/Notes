# JavaScript Execution Context & Window Object

## Call Stack & Execution Context

- When JavaScript starts executing in **V8**, the **Global Execution Context (GEC)** is created first and pushed onto the Call Stack.
    
- When JavaScript reaches a function:
    
    - A new **Function Execution Context (FEC)** is created.
        
    - It is pushed onto the Call Stack, above the existing context.
        
    - The function executes inside this context.
        
- When the function finishes execution, its execution context is popped out of the Call Stack.
    
- Once the entire script finishes executing, the Global Execution Context is also popped out of the Call Stack.
    

---

## Window Object

- Even before the Global Execution Context is created, the browser environment (e.g., Chrome) creates the `window` object.
    
- The `this` keyword in the global scope points to the `window` object (in a browser's classic script).
    

### Global Variables & Functions

Anything we declare in the global scope using `var` or a function declaration is generally added to the `window` object in a browser's classic script.

```
var a = 10;

function speaker() {
    var a = 100;
}
```

### Example

```
console.log(window);
```

You can access global `var` variables and function declarations through the `window` object:

```
console.log(window.a);        // 10
console.log(window.speaker);  // function speaker() { ... }
```

Since `window` represents the global object in a browser:

```
console.log(this); // window
```

> **Note:** `let` and `const` declarations do not become properties of `window`, unlike global `var` declarations and function declarations in classic browser scripts.
